## 修复 WebUI 重启后任务队列丢失
- 问题：WebUI 后端的任务队列存储在内存中（`queue_tasks: dict`），重启后全部丢失；但 TTS 服务端任务仍在运行。
- 修复：在 FastAPI `startup` 事件中增加 `sync_tts_tasks`，自动调用 `GET /api/tasks?limit=50` 从 TTS 服务同步任务状态：
  - 将 TTS 的 pending/running 映射为 WebUI 队列的 RUNNING
  - completed 映射为 SUCCESS，failed 映射为 FAILED
  - 恢复的任务名称为"恢复任务 (tts_task_id)"
  - 如果有运行中任务，设置 `current_task_id` 并通过 `_resume_polling` 恢复轮询，任务完成后自动更新状态和音频 URL
- 修改文件：`webui-backend/server.py`，py_compile 通过。

## 队列任务磁盘持久化
- 问题：用户担心 TTS 服务停了或 WebUI 重启后提交的数据（lines、voices、params）会丢失。内存队列无法保证数据安全。
- 修复：在 `webui-backend/server.py` 增加队列磁盘持久化机制：
  - 持久化目录：`data/queue/*.json`，每个任务一个文件。
  - `_persist_task`：在任务创建、状态变更（运行/完成/失败/取消）、轮询完成时写入磁盘。
  - `_load_persisted_tasks`：启动时从磁盘加载所有持久化任务，恢复排队顺序。
  - `_delete_persisted_task`：取消或清空已完成任务时删除磁盘文件。
  - 启动流程重构为 `on_startup`：
    1. 先从磁盘加载持久化任务
    2. 对运行中且有 tts_task_id 的任务恢复轮询
    3. 从 TTS 服务同步磁盘上不存在的任务
    4. 如果有排队中任务，触发队列处理
  - `_resume_polling` 增加：TTS 返回 404 时标记"TTS 任务不存在（TTS 服务可能已重启）"，任务数据保留在磁盘。
- 各种场景下的数据安全：
  - WebUI 重启、TTS 不停：磁盘恢复任务 + 恢复轮询，正常完成
  - WebUI 重启、TTS 也重启：磁盘保留任务数据，状态标记失败，用户可看到原始提交
  - 两个都不停：正常流程不变
- py_compile 通过。

## 修复破音和异常 s 音
- 问题：生成的音频偶尔破音；全中文中偶尔出现异常 s 音。
- 原因分析：
  1. 破音：IndexTTS2 输出的 WAV 峰值过高，未做归一化直接拼接
  2. 异常 s 音：temperature=0.8 过高 + repetition_penalty=10.0 过高，模型为避开重复 token 生成异常音素
- 修复 1 - 音频归一化：`podcast_engine.py` 的 `_apply_speed` 改为无论 speed 是否为 1.0 都执行 ffmpeg loudnorm 滤镜（I=-16:TP=-1.5:LRA=11），统一响度并限制真峰值，防止破音。
- 修复 2 - 调整默认采样参数：
  - temperature: 0.8 → 0.6（降低随机性）
  - top_p: 0.8 → 0.75（收紧采样范围）
  - top_k: 30 → 20（限制候选 token 数）
  - repetition_penalty: 10.0 → 5.0（避免过度回避常见音素）
- 同步修改：podcast_engine.py, tts-server/server.py, webui-backend/server.py, webui-frontend/src/types/index.ts, ParamsPanel.tsx（增加参数提示）
- 前端 build + 三个 py_compile 全部通过。

## 推理速度优化
- 用户反馈生成速度慢。检查服务器资源图：24GB 显存只用 8.5GB，CPU 几乎空闲，瓶颈在串行推理。
- 优化 1 - 降低默认 num_beams：从 3 降到 2，beam search 对 TTS 质量提升有限但慢 50%。
- 优化 2 - 增加 infer_concurrency 参数（1-4 worker）：利用 24GB 显存空余空间，2 路并发可缩短一半总时长。
  - 实现：podcast_engine.synthesize_podcast 用 ThreadPoolExecutor 并发调度，PyTorch CUDA 操作释放 GIL。
  - 单线程时与原行为一致；多线程时按 idx 排序拼接保证最终顺序。
- 同步修改：podcast_engine.py, tts-server/server.py, webui-backend/server.py, webui-frontend/src/types/index.ts, ParamsPanel.tsx（新增并行推理数输入框 + 说明）。
