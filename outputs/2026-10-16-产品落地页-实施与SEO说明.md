## 3. 关键决策与理由（含代价）

### 3.1 为什么把落地页做成**独立文件** `dist/landing.html`，而不是塞进 `index.html` 的 `#root`

- **问题**：本站是 SPA，`index.html` 的 `<body>` 只有一个 `<div id="root"></div>`，正文全靠 JS 渲染。Google 会执行 JS，**百度不保证**——落地页要承担"被搜到"，正文就必须是静态的。
- **否掉的方案**：把静态正文塞进 `index.html` 的 `#root`。代价是——`index.html` 同时服务 `/docs`、`/dubbing`、`/account`，塞进去等于**每个工作页在 React 接管前都会闪一下落地页内容**；而且这些路由的原始 HTML 会与 `/` 高度重复，等于自己跟自己抢词。
- **采用的方案**：独立文件 `dist/landing.html`（`react-dom/server` 的 `renderToStaticMarkup` 在构建期生成），nginx `location = /` 优先吐它。**两个问题都没有**。
- **代价**：多了构建产物与一条 nginx 规则；产物缺失时要有回落（已做，见下）。

### 3.2 nginx 的两条规则

```nginx
location = /            { try_files /landing.html /index.html; }   # 有产物就吐静态，没有就回落 SPA
location = /landing.html { return 301 /; }                          # 同一内容不给第二个可收录 URL
```

`try_files` 的第二个参数是**回落**：产物缺失时内部跳回 `index.html`，React 会渲染同一个落地页组件——所以这条规则在"产物在"和"产物不在"两种情况下都不会 404。`/docs`、`/account`、`/podcast`、`/dubbing` 走原来的 `location /`，行为不变。

### 3.3 为什么抽出一个 `lib/router.ts`

`lib/auth.ts` 在**模块作用域**读 `localStorage`。落地页的预渲染跑在 Node 里，依赖链一旦碰到它就会抛错。所以把 `navigate()` 挪到 `lib/router.ts`，`auth.ts` 只做 `export { navigate } from "./router"`——**老引用路径一个都没变**。

### 3.4 为什么预渲染产物必须打成 CJS

`react-dom/server` 的 Node 入口内部 `require("stream")`，打成 ESM 会在运行时报 `Dynamic require of "stream" is not supported`。所以 esbuild 用 `format: "cjs"` + `createRequire` 加载。**这一条不写注释的话下次重构必然重踩。**

### 3.5 内容单一数据源：`src/landing/content.ts`

页面上的每个数字会同时出现在三处：**页面正文**、`<head>` 的 title/description、**JSON-LD 结构化数据**。结构化数据与可见正文不一致属于"误导性标记"，会被判罚——所以它们必须来自同一份常量，而不是三处手抄：

- 计费/赠送/签到 → `webui-backend/app/membership/service.py`
- 套餐与价格 → `app/membership/packs.py` 的 `PACKS`（`verify-landing-numbers.js` 会验价格递增、每积分单价递减、`bonus` 与价格对得上）
- 音色条数 → `data/preset-voices/manifest.json`(65) + `data/breezeblue/voices.json`(310) = 375
- 时长折算 → 复用 `lib/format.ts` 的 `TTS_CHARS_PER_SECOND`

`content.ts` 文件头写了一张"改口径时按这个清单逐条核对"的溯源表。

**刻意不写的结构化数据**：不写 `aggregateRating`（没有真实评分数据，编一个就是欺骗）、不写 `Review`、不承诺"永久免费 / 全网第一"。

### 3.6 图片水印：为什么不是裁掉

ImageGen 产物右下角固定带「AI生成 / WORKBUDDY」灰字水印（尺寸约 120×52、距右下各 8px，5 张一致）。**硬裁会切到构图**，所以改用**左邻域克隆覆盖 + 局部高斯模糊**，再放大角落逐张复核确认干净。原图留在 `outputs/landing-images/`（18 MB，已 gitignore），需要重做时从原图起。

### 3.7 FAQ 用原生 `<details>`

不执行 JS 也能展开——静态 HTML 的正文里 10 条答案全都在 DOM 里（脚本断言：10/10 默认收起、最短答案 71 字）。

### 3.8 落地页**绕开**登录态 gate

`App.tsx` 里原本的逻辑是"登录态恢复完成前先渲染 loading 圈"。落地页是纯静态内容、不依赖登录态，所以对 `/` 直接放行：

```tsx
const Page = resolvePage(path);
if (path === "/") return <Page key={path} />;   // 首屏页面不该先闪一个 spinner
if (!ready || needsLogin) return <BootSpinner />;
```

另外 `wb-mode`（"上次用哪个工作台"）**只在两个工作页写**：否则一个本来会被迁移到 `/dubbing` 的老用户，只是看了一眼落地页就丢了这条便利。

### 3.9 路由与收录边界

- `/` → 落地页（免登录）｜`/podcast`、`/dubbing` → 两个工作台 ｜`/account`、`/account/orders` ｜`/docs`（免登录）
- 未知路径**显式回落 `/podcast`**（保持旧行为）
- `robots.txt` 把 `/api/`、`/account`、`/podcast`、`/dubbing`、`/index.html`、`/landing.html` 全部 `Disallow`——登录后面和重复 URL 不该消耗抓取预算。

## 8. 本次顺带修掉的 4 个问题

这几个都不是"顺手美化"，而是**不修会真出问题**的：

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | **移动端「试听」区卡片右侧被切掉 13px**（390/360px 下） | 卡片是栅格子项，默认 `min-width:auto`；卡内 `p.truncate` 是 `nowrap`，其 min-content≈234px 把栅格轨道顶到 **343.92px**，而 390px 视口可用宽只有 271px → 溢出 73px，被根节点 `overflow-x-hidden` 切掉 13px。**算式精确对上**：边框2 + p-4内边距36 + 按钮54 + gap18 + 内层234 = 343.92 | 给两层栅格子项补 `min-w-0`（`SamplePlayer` 卡 + 右列容器），并在代码里写明"不能省" |
| 2 | **页面自我打脸的数字**：案例标题写「3 分钟读书分享音频」「5 分钟双人播客对谈」，而紧挨着的成本行是「约合 1 分钟」 | 标题是手写的、成本行是算出来的 | 标题改为「（约 1 分钟）」，与文稿实际长度一致 |
| 3 | 案例 A 的 params 手写「约 300 字」，实测 248 字（成本行显示 13 积分） | 同上 | 改为「约 250 字」，并写明这是实测值 |
| 4 | **验收脚本对问题 1 是漏判的** | 断言只比 `documentElement.scrollWidth - clientWidth`，而根节点有 `overflow-x-hidden` ⇒ 这个差值恒为 0，越界内容被**静默裁掉** | 断言改为：同时找越界元素，并区分"故意出血的装饰图（`pointer-events-none`）"与"真被切的内容"；后者任何一个存在即判失败。顺带补了 360px 档 |

### 留下的三个检查脚本

它们本身就是这次的价值沉淀——**问题 2、3 那类"手写数字 vs 算出数字"的毛病不报错、不构建失败、肉眼也容易漏**：

- `verify-landing-classes.py`：Tailwind 类名写错不报错只静默失效（项目里已有 `Header.tsx` 的 `w-4.5 h-4.5` 死类实例）。
- `verify-landing-numbers.js`：**它的匹配刻意不要求"约"字**——本次两处时长错账恰恰是裸写的「5 分钟…」；只查「约 N 分钟」会整片漏过。已实测：把标题改回「5 分钟」→ 退出码 1 并指出是哪个字段。
- `verify-landing-page.js`：端到端 30 项，含"静态 HTML 不执行 JS 也有正文"与"FAQ 结构化条目数 == 页面可见问答数"。

## 9. 已知边界与剩余风险（不粉饰）

1. **中文 SEO 没有速效药。** 落地页解决的是"能被收录"（静态正文 + 结构化数据 + sitemap），不解决"排名靠前"——排名取决于站点权重、外链、内容更新频率与竞争对手。**本次没有写任何搜索量数字**，因为那要接百度指数 / 5118 / Ahrefs 才能量化，凭空写就是编。建议上线后到百度搜索资源平台看实际抓取与展现，再决定投哪几个词。
2. **`sitemap.xml` 的 `lastmod` 是手写日期**。纯静态文件、构建期不参与，改了页面要手动更新（已在文件里注释提醒）。
3. **落地页文案里的时长都带"约"、只给量级**（`fmtDuration` 的注释里写了原因）：同一内容换读法（「230」读「二三零」vs「两百三十」）或改标点密度，实测时长能差 20–40%。用户按"65 分钟"去规划节目、做出来 50 分钟会觉得被坑。
4. **试听素材是音色的「参考音频」片段，不是合成产物**。页面文案已明确说明（"用来判断像不像你要的；最终效果还会受语速、情绪与停顿影响"）——这点必须保留，否则是误导。
5. **图片是 AI 生成的抽象图**，不是真实产品照片。视觉风格统一（暗色 + 星云 + 玻璃拟态），但如果你日后要品牌一致性（比如换主色），这 5 张要重出。原图在 `outputs/landing-images/`（未入库）。
6. **`TTS_CHARS_PER_SECOND = 5.08` 写死在前端**（既有决定，未改）：改计费单价或换引擎导致语速变化时，**要手动改这一行**，否则落地页的"约 N 小时"会漂。
7. **部署脚本的构建输入清单仍有既有缺口**：`postcss.config.js`、`tailwind.config.js`、`tsconfig*.json` 也不在 `FRONTEND_SRC` 里，改它们同样会被自检漏判。本次只补了我新增的 `public/` 与 `scripts/`（我的改动引入的构建输入），其余三项属既有问题、未擅自动——要补的话是在 `tools/deploy_g1_autodl.sh` 第 94 行那一个变量里加三个路径。
8. **`/landing.html` 直链会 301 到 `/`**，所以调试静态产物时别直接开这个 URL 看（会跳走）；要看原始产物读 `webui-frontend/dist/landing.html` 文件。
